# ClashHalo 局域网网关中枢配置指南

ClashHalo 的「局域网网关」会把 Mac 变成局域网内的代理出口和 DNS 接管点。适合旁路由、家庭设备统一接管和临时共享网络这类场景。

## 前置条件

- Mac 已连接到局域网
- 已安装并可正常启动 ClashHalo
- 已安装并可连通特权 Helper（开启网关会自动检查；密码前有中文说明）
- 网关依赖 **TUN（Root）**；开启网关时若 TUN 未开，会先拉起 TUN

## 开启方式

1. 打开 ClashHalo 的「网络」页面。
2. 开启 **局域网网关 (旁路由) / 网关中枢**。
3. 按提示完成 Helper / TUN 授权（首次会弹出管理员说明 + 密码框）。
4. 开启后，同一页的 **已接入设备** 会列出局域网客户端（IP、活跃连接、上下行速率）。

> 网关开关是**用户意图**，会写入本机偏好。冷启动不会因为 config 里残留 `allow-lan` / `dns.listen: 0.0.0.0:53` 而自动打开。若开关关闭时仍发现残留 `0.0.0.0:53`，App 会清回 `127.0.0.1:1053` 并关闭 IP 转发。

## 配置接入设备

在需要接管的设备上，把网络参数改成手动：

- **IP 地址**：同网段内未占用地址，例如 `10.1.1.83` 或 `192.168.1.150`
- **子网掩码**：通常是 `255.255.255.0`
- **网关 / Router**：填写 Mac 的局域网 IP
- **DNS**：填写 Mac 的局域网 IP

保存后重新连接网络，设备流量就会经过 ClashHalo。

### 已接入设备如何识别

- App 从 mihomo `/connections` 的 `metadata.sourceIP` 聚合设备列表
- 会过滤本机 IP、loopback，以及 fake-ip 段 `198.18.0.0/15`（本机进程在 fake-ip 模式下的 sourceIP）
- 无活跃连接且超过约 10 分钟未见的设备会从列表移除
- Zashboard 若能看到某 IP 的连接，而 App 列表为空，优先检查是否在网关开关关闭状态（列表仅在网关开启时更新）

### 流量数字怎么读（v1.1.11 起）

- **速率**是按两次采样之间的**实测经过时间**换算的真实 B/s。v1.1.11 之前它是「两次轮询之间的字节增量」却按 B/s 显示，而轮询间隔随页面变化（连接页 1.5s / 其他页 3s / 后台 30s），所以同样的流量会读高 1.5～20 倍。
- **总量**是「该设备所有活跃连接的绝对字节数」加上「已关闭连接的累加值」。因此连接关闭的瞬间总量连续、不跳变，也不会出现假的速率尖峰。v1.1.11 之前总量由增量累加而来，短连接（局域网流量的绝大多数）在两次轮询之间生灭，字节一次都没被计入，读数会明显小于内核。
- 设备列表在**网络页或仪表盘**可见时按 1 秒刷新，其他情况 3 秒。切换页面只影响刷新快慢，不影响数值准确性。
- 设备重新出现在列表里（此前被 10 分钟空闲规则移除）会从 0 重新计数——这是列表，不是长期账本。长期统计请看仪表盘或 Zashboard。

### 仪表盘卡片

仪表盘上有一张「网关已接入设备」卡片，按**当前速率**降序（网络页那个按最近活跃排序）。网关模式关闭、或开着但无设备接入时，卡片不显示。

## 家庭路由器方案

如果想让全屋设备自动接管，可以在主路由器里把 DHCP 的默认网关和 DNS 指向 Mac。

1. 给 Mac 绑定固定局域网 IP。
2. 把路由器 DHCP 的默认网关改成这个 IP。
3. 把首选 DNS 也改成这个 IP。
4. 保存后重启路由器。

这种方案的代价是：Mac 一旦休眠、关机或退出 ClashHalo，所有接入设备都会失去网络。

## 备用方案（仅系统代理 / HTTP 共享）

若不想开网关中枢（不做 IP 转发），只想让设备显式走 HTTP/SOCKS：

1. 在 ClashHalo 打开 **Proxy（系统代理）** — v1.1.4 起会自动确保 `allow-lan`（及必要的 bind-address）。
2. 在设备的代理设置里填：
   - **代理地址**：Mac 的局域网 IP（如 `10.1.1.20`）
   - **端口**：混合端口（默认 `7890`，以当前配置为准）

这个方式只覆盖显式配置了 HTTP/SOCKS 代理的流量，不适合「只改网关+DNS」的透明接管（透明接管请用上文网关中枢）。

## 常见问题

- **设备连不上网**：先确认 Mac 的局域网 IP 没变，网关和 DNS 都填的是同一个地址；确认网关开关仍开启、TUN 仍开启。
- **开启后没流量**：检查内核是否运行、`allow-lan` 是否为 true、DNS listen 是否为 `0.0.0.0:53`。可用 `sudo netstat -an -p udp | grep '\.53'` 确认端口确实绑上了，再用 `dig @<Mac的局域网IP> example.com` 确认真的有人应答。
- **日志报「网关 DNS 未在 53 端口监听」但设备其实正常**：v1.1.11 起，放弃自动重载后仍会每 5 分钟静默复查，监听一旦恢复会自动解除并记录一行 `网关 DNS 已恢复在 53 端口监听`。此前这条错误会一直挂着，需要手动开关网关模式才能复位。若日志持续报此错**且** `dig` 确实无应答，看给出的占用详情——通常是别的解析器（dnsmasq、AdGuard Home 等）先占了 53。
- **冷启动开关自己亮了 / 断网**：v1.1.3 起已修复 config 残留推断。若仍异常，检查 `~/Library/Application Support/ClashHalo/config.yaml` 的 `dns.listen` 是否被手动改回 `0.0.0.0:53`，以及 `sysctl net.inet.ip.forwarding` 是否被其他工具打开。
- **已接入设备列表为空**：确认网关开关开启、窗口在前台；在「连接」页确认是否有非本机 `sourceIP`；Zashboard 可作对照。
- **休眠后失效**：不要让 Mac 自动睡眠，或改用更稳定的常开设备。
